The long version

I've been building software since I was ten years old.

It started with games. Unreal Engine blueprints, then Unity, then a slow obsession with how computers actually work underneath. That path took me through graphics, assembly, OS development, and one accidental rebuild of ASP.NET from scratch before I discovered it already existed.

Today I ship full-stack software for clients and product teams, and I publish open-source .NET libraries on NuGet.

What I'm good at

Where my depth actually is.

.NET, end to end

ASP.NET, EF Core, Blazor, .NET MAUI, Razor, and MudBlazor. I've shipped production systems in all of them and I know where each one fits.

Full-stack delivery

From database schema to UI to deployment. I'm used to owning the whole pipeline of a project, not just a slice of it.

Architecture & documentation

Interfaces before implementations. Decision records before the code that depends on them. Documented systems outlast undocumented ones.

Cross-platform & mobile

.NET MAUI, Blazor Hybrid, Flutter, Android SDK. One codebase, several targets. I know where the abstraction holds and where it leaks.

Systems & low-level

C, C++, Rust, and x86 assembly. Graphics, tooling, and the kind of work that needs to be close to the metal.

Security & algorithms

Security-aware low-level work: authentication and login systems, protocol and algorithm analysis, and designing new algorithms when the existing ones do not fit the problem.

AI integration & inference

How I work

What a project looks like when I'm on it.

The style of working with me, in four points.

01

Interfaces before implementations

Every system I build starts with the shape of the interfaces. Replaceability is a feature, not a nice-to-have.

02

Decisions written down

Every architectural choice ships with its decision record. Alternatives, tradeoffs, consequences. The reasoning is the product.

03

Weekly progress you can see

Working software in your hands every week. If something is wrong you find out in week two, not week twelve.

04

Own the outcome

Once I'm on a project, I'm accountable for what ships. Not just the code I wrote. The full deliverable.
