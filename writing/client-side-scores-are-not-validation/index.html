Client-side scores are not validation

The academy typing tool calculated scores in the browser. Anyone with DevTools could change the number and submit it. The fix was not a better lock. It was moving the trust boundary.

Security · Blazor · .NET

The exploit was one edit

The previous tool calculated the score in JavaScript and submitted the final number. A student could open DevTools, change the number, and submit. The teacher had no way to know whether a score was real.

The obvious fix is to make cheating harder. Block right-click, disable DevTools, minify the JavaScript. Each of those is a deterrent. None of them changes who is allowed to decide the score.

Deterrents are not a trust boundary

Anything that runs in the browser can be changed by the person using the browser. Obfuscation raises the effort. It does not create trust. The browser is still the place where the number is produced.

The useful question is not "how do I stop them from editing this?" It is "why is the browser deciding this at all?"

Re-grade the raw input

The rebuilt platform moved grading to the server. The browser submits the raw input: the typed text, the timing, and the target paragraph. The server computes the score. The client never sends a number.

Forging a score now means forging a complete typing record that matches the target text. At that point, the cheapest way to fake the result is to type the text.

The teacher could trust the score because the authority moved. The UI did not need to become unhackable. It needed to stop being the judge.

The same pattern outside typing

This is not a typing problem. Any score, price, permission, or eligibility check that the browser decides can be changed in the browser. If the value matters, the server should own the calculation and the client should send inputs.

The pattern is the same in commerce, assessments, access control, and anywhere the UI is treated as a security boundary. The UI is a presentation layer. It is not an authority.

The teacher was the real user

The obvious build was for students: more practice modes, better keyboard animations, a nicer typing view. But the person drowning in work was the teacher. She distributed every paragraph to every student by hand and reviewed every submission manually.

The platform turned distribution into one action: one assignment, one class, one push. That change mattered more than any student-facing feature, because it removed the work that made the tool expensive to run.

Takeaways

Three things worth keeping.

  • 01 If the browser decides a value that matters, the browser can lie.
  • 02 Deterrents raise effort. They do not create a trust boundary.
  • 03 Move the calculation to the server and accept raw inputs, not final scores.
